# BOSS V9.1 — `--inspect` warm-up crash fix

## Root cause

`BossStrategy.analyze()` created its empty-history `StrategyResult` using positional arguments. After `predictor_top_decile_net_return` was added to the dataclass, the constructor values shifted: the string `"warming up"` was assigned to the numeric `predictor_brier` field. `print_dashboard()` then attempted to format that string with `:.3f`, raising `ValueError: Unknown format code 'f' for object of type 'str'` when the live database had no usable history yet.

## Fix

- Replaced the positional empty-result construction with keyword arguments for every field.
- Added regression tests for the empty-history metric types and for printing the exact dashboard in the no-history/warm-up state.
- Added the missing `.env.example` referenced by `README.md` and `DEPLOYMENT.md`. It includes the documented API host, blank credential fields, current competition cadence, fees, strategy settings, and the requested zero values for internal turnover/order/rotation and global halt controls.

## Validation

- 46 unit tests passed.
- Python compilation passed.
- The dashboard no-history path now prints `MODEL GATE: warming up` and `brier=1.000` without crashing.
- ZIP integrity check passed.

This fix addresses the reported traceback. It does not perform live order submission or prove strategy profitability.
